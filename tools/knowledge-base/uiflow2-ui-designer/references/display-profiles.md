# Display Profiles

先按能力分流，再设计画面。不要维护容易过期的“产品名到分辨率”硬编码大全；目标板卡文档和运行时查询是事实源。

## 能力探测

调用 `M5.begin()` 并设置所需旋转后，再读取最终尺寸。EPD 能力以目标 display
对象上的 `isEPD()`（当前官方 display 文档示例写作 `Display.isEPD()`）和板卡文档为准。

```python
width = M5.Lcd.width()
height = M5.Lcd.height()
is_epd = M5.Lcd.isEPD()
short_side = min(width, height)
```

同时确认：

- 屏幕是矩形还是圆形；相同宽高不能证明是圆屏。
- 是否支持触摸、按键、旋钮或键盘，交互方案不能只看显示能力。
- 目标固件是否支持 m5ui。当前支持范围见 [m5ui overview](../../uiflow2-coder/docs/m5ui/_overview.md)。
- 是否有 PSRAM，以及全屏 buffer 的内存成本。8 bpp 约为 `width * height` 字节，RGB565 约为两倍；双缓冲再乘二，并预留 Python、LVGL 和业务数据空间。

## 常规彩色 LCD

适用于 240 x 135、320 x 240 及更大矩形彩屏。

- 先留统一外边距，再分配标题、主指标、辅助信息和操作区。不要让每块区域同样醒目。
- 320 x 240 触摸界面可从 40 x 40 px 的最小点击区域起步；大屏按比例增大。文字按钮的宽度还要容纳最长标签。
- 新的多控件或多页触摸应用优先 m5ui；高频自定义绘制先选同一 LVGL 页上的
  `m5ui.M5Canvas`，只有 m5ui 不可用时才选 M5GFX Canvas。
- 背景与表面至少有明度差，主色只用于焦点和可操作状态。
- 仪表盘通常不需要高帧率；数值变化时更新局部控件或 Canvas 区域。

## 紧凑竖屏或横屏

短边不大于约 135 px 时，信息密度和稳定布局优先。

- 使用 4 px 基础间距，常用间距为 4/8/12/16；避免多层容器和宽阴影。
- 每屏保留一个主指标或一个主操作，辅助信息压缩成一到两行。
- 按钮高度通常从 36 px 起步；若空间不足，减少按钮数量而不是继续缩小。
- 依赖 `textWidth()`、`fontHeight()` 或 LVGL 文本测量定位单位、数值和右对齐文本。
- 动画优先使用 8 bpp Canvas、局部区域或低复杂度图元，先估算内存再创建全屏 buffer。

## 圆屏

圆屏的方形 framebuffer 四角通常不可见或不适合放置信息。

- 将主数值、状态和核心操作放在中央约 70% 到 78% 直径范围内；边缘用于刻度、进度弧和非关键装饰。
- 用径向层级：外圈状态或刻度，中圈上下文，中心主值。不要把矩形卡片网格硬塞进圆形边界。
- 长文本沿水平中心区排布，必须用真实字体测量；四角不得放按钮、错误提示或电量等关键信息。
- 旋钮和触摸交互要显示当前焦点；圆周运动应映射到角度或弧线，而不是无反馈地修改数字。
- 使用屏幕轮廓遮罩或实机画面检查裁切，代码坐标合法不代表肉眼可见。

## 电子纸

EPD 是状态变化驱动的静态信息界面，不是低帧率 LCD。

- 采用高对比、少颜色、清晰分区和稳定版式；不用淡入、脉冲、粒子或持续进度动画。
- 聚合多项变化后一次刷新，避免循环刷新和无意义的时钟秒级更新。
- `M5.Lcd.isEPD()`、`setEpdMode()` 和支持模式以 [display API](../../uiflow2-coder/docs/hardware/display.md) 为准。
- 页面变化应有明确原因，如用户操作、新数据、分钟级时间变化或状态切换。
- 通过标题、粗细、边框、留白和图标区分状态，不依赖细微灰阶。
- 明确全刷、快速刷新和残影风险；没有实机观察时不得声称残影可接受。

## 16 x 16 LED Matrix

CoreMatrix 等设备按像素画布设计，不套用 LCD 控件体系。支持事实见 [CoreMatrix controller doc](../../uiflow2-coder/docs/controllers/corematrix.md)。

- 使用 1 px 网格和 2 到 4 个主色；先画轮廓和运动关键帧，再补高光。
- 文字仅限经过验证的短数字或小型字形。普通标签、段落、卡片和阴影没有意义。
- 帧率从 8 到 15 FPS 起步；只有实机确认刷新、功耗和观感允许时再提高。
- 限制同时点亮的高亮像素和总体亮度，避免功耗、发热和过曝影响。
- 动画应有清晰轮廓、少量关键帧和稳定节奏；微小亚像素运动在这里不存在。

## 旋转与适配

- 旋转必须在布局计算前确定，之后读取 `width()` 和 `height()`。
- 不按 viewport 缩放字体。为每个显示档案选择实际存在的离散字体，再用网格和留白适配。
- 固定格式部件使用明确宽高；动态文本只改变内容，不应让按钮、仪表或布局跳动。
- 跨分辨率代码使用命名布局常量和少量派生值。若两个屏幕的信息架构明显不同，分别设计 profile，不强行等比缩放。
