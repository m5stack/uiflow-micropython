# Design Directions

风格方向用于统一视觉意图、信息层级和布局选择，不是固定模板。先根据任务、屏幕
比例、信息密度和输入方式选一个主方向；只有能改善表达时再加入一个次要影响。
设备限制始终高于风格：EPD、圆屏、小屏和 LED Matrix 继续遵守
[display-profiles.md](display-profiles.md)。

## 选择流程

1. 用一句话写清页面目标，例如“让操作员 2 秒内看出报警和停机入口”。
2. 标出一个主视觉焦点、一个主操作和最多两个次级信息组。
3. 从下方选择一个方向，再按内容选择布局变体。
4. 定义背景、表面、主强调色、可选辅助强调色、文本和状态色。
5. 用实际存在的语义控件实现；风格不能成为使用未文档化 API 的理由。

## 布局变体

- `hero_metric`：一个大数值或状态占据视觉中心，次级信息围绕或位于底部。
- `gauge_focus`：以 `M5Scale`、`M5Arc`、`M5Bar` 或 `M5Chart` 为中心。
- `split_layout`：主图形与操作/详情分居左右或上下，适合宽屏。
- `list_first`：列表、表格、菜单或设置行为主，标题和状态条为辅。
- `control_first`：一个主要动作加少量高频控件，状态与反馈紧邻操作。
- `status_strip`：顶部或底部承载紧凑连接、电量、告警或运行状态。

不要默认使用标题加 2 x 2 卡片网格。内容只有一个主值时优先 `hero_metric`；
带刻度仪表优先 `gauge_focus`；配置和设备列表优先 `list_first` 或
`control_first`。

## Minimal Status

适合 135 x 240、小型状态屏、确认页、单值读数、ready/error 页面和 EPD。

- **气质**：安静、直接、高可读。
- **构图**：`hero_metric`、`control_first` 或单一状态横幅。
- **色彩**：简单明/暗背景，一个语义强调色，状态色不作装饰。
- **控件**：`M5Label`、`M5LED`、`M5Bar`、一个 `M5Button`；圆屏可用 `M5Arc`。
- **避免**：为了填满空间添加卡片、多个强调色、长说明和微小状态文字。

## Dark Dashboard

适合传感器、能源、电池、车辆、网络和多指标监控 LCD。

- **气质**：专注、技术化、高对比。
- **构图**：`hero_metric`、`gauge_focus`、`split_layout` 或 `status_strip`。
- **色彩**：近黑/深灰背景，略亮表面；数据/网络用蓝青，健康状态用绿，红色仅用于严重异常。
- **控件**：`M5Chart`、`M5Scale`、`M5Arc`、`M5Bar`、`M5LED` 和短标签。
- **避免**：默认白色 chart/list 背景、整屏同色相、四个等权卡片和密集小字。

## Light Control

适合设置、网络配置、表单、设备参数和日常控制。

- **气质**：清晰、克制、实用。
- **构图**：`list_first`、`control_first`、上下分区或宽屏双列。
- **色彩**：浅灰/白背景，白或轻灰表面；蓝、青或绿用于主操作，红色只用于破坏性动作。
- **控件**：`M5Switch`、`M5Slider`、`M5Spinbox`、`M5Dropdown`、`M5Roller`、
  `M5TextArea`、`M5Keyboard`、`M5Button`。
- **避免**：低对比浅灰文字、过亮大面积主色、不同尺寸控件无规律混排。

## Industrial HMI

适合生产、PLC、马达、维护、报警、参数和多通道状态。

- **气质**：可靠、稳定、快速扫描。
- **构图**：报警优先、参数行列、过程总览、操作区或状态表。
- **色彩**：石墨/中性背景；绿=运行，黄/橙=警告，红=报警/停止，蓝=信息/选中。
- **控件**：`M5Table`、`M5List`、`M5Bar`、`M5Switch`、`M5LED`、
  `M5Scale`、`M5Chart`、`M5Button`。
- **避免**：装饰性红色、灰底灰字、危险操作与普通操作相邻、报警文字过小。

## Appliance Friendly

适合家电、咖啡机、厨房设备、模式选择、进度和桌面助手。

- **气质**：友好、触感明确、下一步清楚。
- **构图**：模式焦点、产品选择、制作进度、一个大主操作或维护状态。
- **色彩**：暖灰、柔和深色或产品色；琥珀、橙、青作主色，完成状态用绿。
- **控件**：大尺寸 `M5Button`、`M5Image`、`M5Bar`、`M5Arc`、
  `M5Roller`、`M5Slider` 和短标签。
- **避免**：工业表格式密度、多个等权按钮、依赖图片作为唯一含义、标签过长。

## Futuristic HUD

适合 AI 面板、高冲击演示、智能设备和科技仪表，但只用于资源允许的彩色 LCD。

- **气质**：锐利、克制的未来感，不是效果堆叠。
- **构图**：`gauge_focus`、中心 HUD、`split_layout` 或对齐的数据控制台。
- **色彩**：黑/深蓝/深灰背景，一个高亮青、蓝、紫或绿，可加一个低饱和辅助色。
- **控件**：`M5Scale`、`M5Arc`、`M5Chart`、`M5Bar`、`M5Line`、
  `M5Canvas` 和少量语义操作控件。
- **避免**：模拟浏览器 glow/blur、三种以上霓虹色、装饰线遮挡数据、蓝底蓝字。

## Anti-Sameness

- 同类请求不要固定复用相同卡片网格；根据数据主次更换视觉中心与布局变体。
- 至少让背景明暗、强调色、布局变体、信息层级、表面形状中的两项匹配本次内容，
  而不是沿用上次答案。
- 同一页面内部必须统一，跨无关页面不强求完全相同；多页应用保留品牌色和状态语义，
  允许页面按任务改变密度与构图。
- 差异必须来自内容和交互，不使用随机颜色、随机位置或无意义动画制造“不同”。

## LVGL/UIFlow2 边界

- 仅使用相邻 `uiflow2-coder` 文档和当前源码确认存在的 m5ui 控件、字体、part、
  state 和方法。
- 卡片/面板效果使用已验证的控件背景、页面分区或 Canvas 背景；禁止编造
  `M5Obj`、`tileview`、`digitalclock`、`animimg` 等不存在的 UIFlow2 包装器。
- 不复制 CSS 阴影、模糊、滤镜或响应式断点；通过实色、边框、透明度、层级和留白
  达到相同信息目的。
