# UI Review Checklist

审查结果按 `P0`（无法使用或高风险）、`P1`（明显影响理解/交互/性能）、`P2`（可改进的视觉质量）排序。每条问题都要给文件、代码位置、现象、证据和最小修复。

## 设备与 API

- [ ] 目标板卡、旋转、宽高、屏幕形状和显示类型已确认。
- [ ] 已选择目标固件上最高可行的渲染层级；若降级，记录 import、控件、RAM 或帧率原因。
- [ ] `M5.begin()`、`M5.update()`、`m5ui.init()` 和页面加载顺序符合官方文档。
- [ ] 只使用一个主要 UI 体系；`m5ui` 控件有正确 `parent`。
- [ ] `M5.Lcd`、Widgets、m5ui/LVGL 的颜色、字体和对象没有互相传错。
- [ ] 每个构造函数、事件、绘图、图表和字体符号都能在当前官方文档或源码中找到。
- [ ] EPD、圆屏、Matrix 和触摸支持没有靠产品名或经验臆测。

## 视觉层级

- [ ] 每屏有一个主任务和一个主视觉焦点。
- [ ] 背景、表面、主色、文本和状态色形成清晰层级。
- [ ] 字体字号不超过 2 到 3 个主要层级；真实字体下文字可读。
- [ ] 间距、圆角、边框和阴影是有节奏的，而不是每个元素独立设置。
- [ ] 装饰不遮挡数据，不与主状态竞争，不只是为了“高级感”。
- [ ] 灰度下仍能区分主值、标题、操作和告警。

## 布局与文本

- [ ] 坐标来自屏幕尺寸、边距、网格和测量值。
- [ ] 长标题、城市名、单位、错误消息和动态数值都有溢出策略。
- [ ] 固定格式控件的宽高稳定；更新数据不会让邻居跳动。
- [ ] 圆屏四角没有关键内容；小屏没有被缩小到不可读的正文。
- [ ] 触控/按键命中区足够大且与视觉边界一致。

## 状态与交互

- [ ] normal、pressed/focused、selected、disabled 状态可辨。
- [ ] loading、empty、error、offline/stale、success 都有可理解的画面。
- [ ] 状态不只依赖颜色；有文字、图形、轮廓或亮度辅助。
- [ ] 事件回调不做网络、文件、长时间等待或大对象创建。
- [ ] 操作有即时反馈，失败有下一步，旧数据不会伪装成最新。

## 动效与性能

- [ ] 静态背景只绘制一次；动态内容使用局部重绘或复用 Canvas。
- [ ] 多步骤图形没有直接逐笔绘制到屏幕；已使用 m5ui Canvas 或 M5GFX Canvas 的批量/单次提交。
- [ ] 循环没有持续 `fillScreen()`、`clear()`、页面初始化或全屏 buffer 分配。
- [ ] 动效有帧间隔、时间基准、状态机和结束条件。
- [ ] 粒子、点、列表和临时对象数量有上限；没有每帧失控分配。
- [ ] 传感器值经过滤波、限幅和采样/绘制解耦。
- [ ] EPD 没有连续动画；Matrix 使用少量像素关键帧。
- [ ] 报告了内存、帧率、掉帧、残影、功耗或温升的已知限制。

## 验证与交付

- [ ] Python 语法、官方文档链接和静态搜索检查已通过。
- [ ] 有针对目标板卡的串口/触摸/按键/传感器验证步骤。
- [ ] 有相机画面或人工观察才可报告视觉 PASS；否则为 `NOT RUN`/`PARTIAL`。
- [ ] 未经明确授权，没有烧录、擦除、推送或改变设备状态。
- [ ] 最终说明哪些是代码检查结果，哪些是运行结果，哪些仍需真机观察。
