# Layout Recipes

这些是可迁移的结构配方，不是固定坐标模板。先按 [display-profiles.md](display-profiles.md) 确认屏幕 profile，再将尺寸换成派生布局常量。

## 320 x 240 触控仪表盘

适合 m5ui/LVGL 或 m5ui Canvas 混合：

1. 顶部 28 到 36 px：标题、时间或连接状态。
2. 中部约 110 到 140 px：一个主指标或主图形，配单位和状态。
3. 底部 50 到 70 px：两到三个操作或关键辅助指标。
4. 用表面色和 1 px 分隔线建立分组，不让每个分组都成为浮动卡片。

主指标占视觉面积约一半；按钮使用稳定宽高，动态数值预留最长合理宽度。网络更新、空数据和离线应保留同一版式。

## 135 x 240 紧凑信息页

- 顶部保留 20 到 28 px 标题或状态。
- 选一个主值或图标，其他数据降级为短标签和单行值。
- 使用 4 px 网格和少量圆角；减少描边、阴影和并列卡片。
- 需要刷新时只擦除数值和状态区域。参考 [Widgets weather sample](../../uiflow2-coder/assets/examples/widgets/weather_135x240.py) 的 Canvas 分层和缓存策略。

## 仪表 / 进度环

- 背景轨道固定，前景轨道表达当前值，刻度只保留有用阈值。
- 中心放主值和单位，外圈放方向或范围；不要在弧线周围堆长文本。
- 起始角、结束角、顺时针方向和满量程必须在设计说明中写清楚。
- 超限同时使用颜色、文字和形状变化；不要仅改变弧线颜色。

## 列表与设置

- 每行一个主标签和一个值/状态，操作区域保持统一对齐。
- 选中行使用背景或左侧标记；禁用行保留可读文字和原因。
- 长列表用有限可见行和滚动/分页策略，不一次创建不受控数量的控件。
- 空列表显示原因和下一步；加载时保留标题和布局骨架。

## 加载、空、错误和离线页

- **加载**：告诉用户正在做什么；LCD 可以有一个低频状态点或进度弧。
- **空**：说明“没有数据”的原因，并提供刷新、添加或返回动作。
- **错误**：给人能执行的下一步，例如重试、检查连接或返回；保留可用的旧数据。
- **离线**：在标题或状态区明确 `OFFLINE`/`STALE`，不要把数据伪装成最新。
- **成功**：用短暂状态文字或一次轻量高亮确认，然后回到稳定画面。

## 圆屏计时器

- 外圈：剩余比例或刻度。
- 中圈：当前模式和次要状态。
- 中心：大字号时间和唯一主操作。
- 触摸或旋钮焦点使用边框、高亮或反转区域表达；避免把按钮放在四角。

## 电子纸信息页

- 标题区、主信息区、列表区和更新时间区使用固定分栏。
- 黑白优先，少量灰度只用于层级；关键告警用文字、图标和粗边界重复表达。
- 仅在页面数据发生变化或用户操作时刷新；把分钟级变化聚合后再更新。
- 版式在快速刷新和全刷模式下保持一致，不为动画增加额外中间态。

## LED Matrix 像素页

- 先选择 1 个主符号或 2 到 4 个字符，再决定是否需要动画。
- 轮廓、眼睛、方向箭头和进度条比细节更重要；颜色数量少而稳定。
- 可用按钮或 IMU 改变模式，但每次状态变化都应在像素上明显可辨。
- 高亮区域和刷新频率要受控；无实机观察时只能报告代码层设计完成。

## 共享布局计算

```python
margin = max(4, min(width, height) // 20)
content_w = width - margin * 2
title_y = margin
footer_y = height - margin - footer_h
```

- 用命名常量表达层级和区域，不在绘制函数里散落无关数字。
- 需要居中时用真实文本宽度：`x = (area_w - text_width(text, font)) // 2 + area_x`。
- 所有动态区域定义固定矩形；内容变化只能更新内容，不能改变相邻区域尺寸。
