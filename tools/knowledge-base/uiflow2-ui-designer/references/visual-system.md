# Visual System

UIFlow2 的设计系统应足够小，能直接变成 MicroPython 常量和布局计算。不要生成 Web token 大全。

## 先定设计概念

用一句话确定用途和气质，例如“安静的环境监测仪表”“高对比运动计时器”“像素化状态精灵”。每个视觉决定都应服务这句话。

新建、重设计或美化界面时，按 [design-directions.md](design-directions.md)
选择一个主方向和一个适合内容的布局变体。风格不能覆盖设备 profile，也不能为了
“有设计感”引入未支持的控件或效果。

## 最小 Token 集

代码至少使用命名常量表达以下角色：

```python
COLOR_BG = 0x0B1014
COLOR_SURFACE = 0x182128
COLOR_PRIMARY = 0x38B8C8
COLOR_TEXT = 0xF3F7F8
COLOR_MUTED = 0x98A8AE
COLOR_SUCCESS = 0x58C78A
COLOR_WARNING = 0xF1C75B
COLOR_ERROR = 0xE9675A
```

- 一屏通常只需要一个主色。成功、警告和错误色按语义保留，不把它们当装饰色。
- 背景、表面、边框和文本要有可见明度差。弱文本仍需在真实面板亮度下可读。
- 颜色不是唯一信号：离线状态同时显示文字或图标，选中状态同时改变边框、形状或亮度。
- 避免整屏只用同一色相的深浅变化；中性色承担结构，主色承担焦点，状态色承担语义。

## 间距与网格

- 短边不大于 135 px：4 px 基础单位，常用 4/8/12/16。
- 240 到 320 px：6 或 8 px 基础单位，常用 8/12/16/24。
- 更大触摸屏：8 px 基础单位，按内容密度扩展到 16/24/32。
- 同级元素使用同样间距；关联元素的间距小于不同分组之间的间距。
- 圆角保持少量档位，例如 0/4/8。半径不能大到把所有面板变成胶囊。
- 边框通常 1 px 足够；阴影只用于可交互层级或浮层，不给每个面板都加阴影。

## 页面与控件协调

页面背景不会自动修正所有子控件。当前 m5ui 源码中部分控件默认白色、浅灰或蓝色，
深色或品牌化页面必须主动检查。

1. 先确定 page 和主要表面背景，再创建可见控件。
2. 从具体控件文档和源码确认构造默认值、可用 part/state 和样式方法。
3. 显式协调 visible default、pressed、checked、selected、focused 和 disabled；
   不假设修改 `lv.PART.MAIN` 会自动覆盖 indicator、knob、items、ticks 或列表子项。
4. `M5Label`、`M5Button`、`M5Checkbox`、`M5List`、`M5Chart`、
   `M5Canvas`、`M5Arc`、`M5Scale` 和 `M5Spinner` 是默认背景/颜色重点检查对象。
5. overlay 型控件应与父背景融合；只有当前文档/源码确认对应 part 与透明度 API 后
   才设置透明背景，不能照搬其他 LVGL 版本。

默认样式恰好符合设计时可以保留，但必须是经过检查的选择，而不是遗漏。

## 字体与文本

字体能力见 [m5ui overview](../../uiflow2-coder/docs/m5ui/_overview.md)。

- 一屏使用 2 到 3 个字号层级：主值、标题/操作、正文/辅助。不要让每段文字都有独立字号。
- m5ui 的拉丁文字使用 `lv.font_montserrat_*`；m5ui 的 CJK 文字分别使用
  `lv.AlibabaPuHuiTi_CN24`、`lv.AlibabaSans_JP24`、`lv.AlibabaSans_KR24`。
- `M5.Lcd` 和 `M5.Widgets` 使用 `M5.Lcd.FONTS`，对应 CJK 名称是
  `AlibabaPuHuiTiCN24`、`AlibabaSansJA24`、`AlibabaSansKR24`。LVGL 与
  `M5.Lcd.FONTS` 的对象名和类型不同，不能互换。
- 先查目标控制器文档；文档未说明时，用 `hasattr()` 检查完整且精确的字体名，
  例如 `hasattr(lv, "AlibabaPuHuiTi_CN24")`，并提供已确认存在的字体回退。
- 数字与单位分层：数字更大，单位更小且靠近基线；先测量数字宽度再定位单位。
- 优先用 `lv.text_get_size()` 或 `M5.Lcd.textWidth()` 测量真实字体；只有设计阶段
  无法运行目标 API 时才用保守估算，并为 padding、图标和单位留额外空间。
- 动态文本区域用最长合理值、负数、小数、错误提示和离线文案验算。超出时优先
  扩宽、增高、缩短文案或重排，再考虑换行/省略/滚动；不要动态缩放整个页面。
- 多语言页面逐种语言检查文字宽度、glyph 覆盖和语言切换控件。语言名应使用当前
  页面字体能覆盖的脚本；无法确认覆盖时不要用缩写掩盖缺字。

## 形状、图标与层级

- 图标优先由圆、线、弧、矩形和三角形组合，或使用已验证的本地 PNG/JPG/BMP。
- 不用 emoji 作为图标；字形覆盖、彩色渲染和基线在嵌入式字体中都不可靠。
- 图片按目标控件像素尺寸准备并保持比例；小图标优先透明背景，避免加载大图后再
  缩成很小的控件浪费 RAM。格式、路径和缩放必须查当前 `M5Image` 或 display 文档。
- 图片不能成为状态或操作含义的唯一来源；同时提供文字、形状、边框或状态色。
- 主视觉可打破严格对称，但操作区和数据列必须对齐。变化应有意图，不能像随机坐标。
- 卡片只用于真正独立的信息组；不要在卡片里再套卡片。
- 装饰图形要避开文本边界，并保持低对比，不与主数据争夺注意力。

## 控件状态

每个交互控件至少规划：

- normal：可操作但不抢夺主信息焦点。
- pressed/focused：颜色、亮度、边框或轻微位移立即反馈；尺寸不引发布局移动。
- disabled：降低对比并保留形状，同时说明为什么不可用。
- selected：与 normal 有稳定且持续的区别。

页面至少规划：

- loading：显示正在进行的动作；LCD 可用有限动画，EPD 使用静态进度文字。
- empty：说明当前无数据，并给出可执行的下一步。
- error/offline：保留最后有效数据时明确标注 stale/offline；不要把整个页面只染成红色。
- success：短暂确认后回到稳定状态，避免无限循环庆祝动画。

## 避免生硬的具体做法

- 让一个元素成为明确焦点，其他元素通过字号、明度和面积递减。
- 使用一致的间距节奏，不把每个控件贴在等距网格的每个格子里。
- 通过局部高光、进度弧、状态点、数字过渡和按压反馈表达变化，而不是所有元素同时移动。
- 用有意义的空白分组；小屏信息少一点通常比把所有内容缩小更专业。
- 完成设计后灰度检查一次：即使去掉颜色，标题、主值、操作和错误状态仍应可区分。
