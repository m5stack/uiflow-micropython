# Visual System

UIFlow2 的设计系统应足够小，能直接变成 MicroPython 常量和布局计算。不要生成 Web token 大全。

## 先定设计概念

用一句话确定用途和气质，例如“安静的环境监测仪表”“高对比运动计时器”“像素化状态精灵”。每个视觉决定都应服务这句话。

常见方向：

| 场景 | 视觉重点 | 避免 |
| --- | --- | --- |
| 工业监控、仪表 | 高对比、稳定网格、明确告警 | 大面积装饰、跳动数字 |
| 消费设备、桌面助手 | 友好造型、柔和层级、清晰反馈 | 所有元素都圆润、持续呼吸 |
| 游戏、玩具 | 鲜明轮廓、节奏、有限粒子 | 过多文字、随机颜色 |
| 电子纸阅读 | 黑白层级、留白、稳定版式 | 动画、细灰线、低对比 |
| LED matrix | 像素轮廓、有限调色板、关键帧 | 普通控件和小字号正文 |

## 最小 Token 集

代码至少使用命名常量表达以下角色：

```python
COLOR_BG = 0x0B1014
COLOR_SURFACE = 0x182128
COLOR_PRIMARY = 0x38B8C8
COLOR_TEXT = 0xF3F7F8
COLOR_MUTED = 0x98A8AE
COLOR_SUCCESS = 0x58C78A
COLOR_WARNING = 0xF1C75B
COLOR_ERROR = 0xE9675A
```

- 一屏通常只需要一个主色。成功、警告和错误色按语义保留，不把它们当装饰色。
- 背景、表面、边框和文本要有可见明度差。弱文本仍需在真实面板亮度下可读。
- 颜色不是唯一信号：离线状态同时显示文字或图标，选中状态同时改变边框、形状或亮度。
- 避免整屏只用同一色相的深浅变化；中性色承担结构，主色承担焦点，状态色承担语义。

## 间距与网格

- 短边不大于 135 px：4 px 基础单位，常用 4/8/12/16。
- 240 到 320 px：6 或 8 px 基础单位，常用 8/12/16/24。
- 更大触摸屏：8 px 基础单位，按内容密度扩展到 16/24/32。
- 同级元素使用同样间距；关联元素的间距小于不同分组之间的间距。
- 圆角保持少量档位，例如 0/4/8。半径不能大到把所有面板变成胶囊。
- 边框通常 1 px 足够；阴影只用于可交互层级或浮层，不给每个面板都加阴影。

## 字体与文本

字体能力见 [m5ui overview](../../uiflow2-coder/docs/m5ui/_overview.md)。

- 一屏使用 2 到 3 个字号层级：主值、标题/操作、正文/辅助。不要让每段文字都有独立字号。
- m5ui 使用 `lv.font_montserrat_*`；`M5.Lcd` 和 Widgets 使用 `M5.Lcd.FONTS`。两类字体对象不能互换。
- 可选 LVGL 字体用 `hasattr(lv, "font_montserrat_20")` 等方式检查，并提供常见字号回退。
- CJK 文本使用文档确认存在的 `M5.Lcd.FONTS.Alibaba*24`，并考虑小 flash 固件不包含这些字体。
- 数字与单位分层：数字更大，单位更小且靠近基线；先测量数字宽度再定位单位。
- 动态文本区域预留最长合理值。超出时使用换行、省略、裁切或滚动，不缩放整个页面。

## 形状、图标与层级

- 图标优先由圆、线、弧、矩形和三角形组合，或使用已验证的本地 PNG/JPG/BMP。
- 不用 emoji 作为图标；字形覆盖、彩色渲染和基线在嵌入式字体中都不可靠。
- 主视觉可打破严格对称，但操作区和数据列必须对齐。变化应有意图，不能像随机坐标。
- 卡片只用于真正独立的信息组；不要在卡片里再套卡片。
- 装饰图形要避开文本边界，并保持低对比，不与主数据争夺注意力。

## 控件状态

每个交互控件至少规划：

- normal：可操作但不抢夺主信息焦点。
- pressed/focused：颜色、亮度、边框或轻微位移立即反馈；尺寸不引发布局移动。
- disabled：降低对比并保留形状，同时说明为什么不可用。
- selected：与 normal 有稳定且持续的区别。

页面至少规划：

- loading：显示正在进行的动作；LCD 可用有限动画，EPD 使用静态进度文字。
- empty：说明当前无数据，并给出可执行的下一步。
- error/offline：保留最后有效数据时明确标注 stale/offline；不要把整个页面只染成红色。
- success：短暂确认后回到稳定状态，避免无限循环庆祝动画。

## 避免生硬的具体做法

- 让一个元素成为明确焦点，其他元素通过字号、明度和面积递减。
- 使用一致的间距节奏，不把每个控件贴在等距网格的每个格子里。
- 通过局部高光、进度弧、状态点、数字过渡和按压反馈表达变化，而不是所有元素同时移动。
- 用有意义的空白分组；小屏信息少一点通常比把所有内容缩小更专业。
- 完成设计后灰度检查一次：即使去掉颜色，标题、主值、操作和错误状态仍应可区分。
